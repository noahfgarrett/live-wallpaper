# Milestone 4 — Effect Regions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (Native execution: the builder session implements every task, then one fresh reviewer checks the whole branch). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Snow can be confined to part of the photo (for example only the sky) or kept out of it (only outside a window), edited in the app with draggable corners and shown the same way on the desktop.

**Architecture:**
- **Core** owns everything that can be tested on the Mac: the region model and its validation, the pure polygon operations, undo history, the CPU mask rasterizer (fill, union, blur, invert) and the editor's interaction rules (`RegionEditor`), which outputs overlay shapes in image coordinates.
- **Rendering** uploads the mask as an R8 texture per scene (1×1 white when there are no regions), multiplies snow alpha by it in `Snow.hlsl`, and draws the editor overlay (outlines, handles) with a small SDF shader.
- **The app** forwards mouse input from the preview `HwndHost` to `RegionEditor` and hands the overlay shapes to the preview renderer, which draws them on top of the scene. **The engine** applies the stored regions to each monitor's scene and accepts a new `UpdateRegions` IPC request for live edits.

**Tech Stack:** .NET 10, WPF + WPF-UI 4.3.0, Vortice 3.8.3 (D3D11/D3DCompiler), xUnit v3. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-19-live-wallpaper-design.md` section 5.8 (and 5.3 for IPC). The approved browser preview on `feat/m0-preview` is the behavioural reference: `prototype/regions.js`, `prototype/regionEditor.js`, `prototype/mask.js`, `prototype/history.js`, their tests, and the Regions section of `docs/snow-model.md`.

**Branch:** `feat/m4-regions`, cut from `feat/m2-m3-app`; the PR targets `feat/m2-m3-app` (stacked on PR #3).

## Global Constraints

- **No new dependencies.** BCL, Vortice 3.8.3 and WPF-UI 4.3.0 only; `dotnet restore --locked-mode` must still pass.
- **Coordinates:** a region is a polygon in normalized image coordinates (0–1 of the *full, oriented* source image), so it stays on the same part of the picture under every scaling mode, including the Center crop.
- **Model values (from the preview):** new quad corners TL, TR, BR, BL at 0.35–0.65; minimum 3 points; soft edge 0–10 % in 0.1 steps, default 1 %; `featherPx = featherPct / 100 × displayed image width`, blur σ = `featherPx / 2`; inverted = holes cut from white; snow alpha × mask red channel; no regions = no mask (white).
- **Limits (builder's call, validated at every boundary):** at most 16 regions, at most 64 points per region; history keeps 100 states.
- **Backward compatible library:** a v0.2.0-m3 `library.json` (schema 1, no `regions` property) must load with empty regions. Do not bump the schema version.
- **Known preview bugs not to port:** overlapping regions with opposite winding cancel (fill each region separately and union); selection survives undo/redo; undo during a drag leaves the drag live; drags can leave the visible part of the image; editing still works with outlines hidden.
- **Deferred, not built:** the 4-point plane homography (spec 5.8 says v1 snow ignores it). `Region.IsPlane` exists because the preview tests pin it; nothing else about planes is built or documented as working.
- **Platform split:** Win32/D3D/WPF tests use `WindowsOnly.Require()` and run on CI (WARP).
- Repo style: 4-space indent, `TreatWarningsAsErrors`, nullable on, explicit return types, conventional commits on `feat/m4-regions`, every UI control works (no phantom features).

## Review Focus

1. **Upgrading from v0.2.0-m3:** an existing library without `regions` must load unchanged, not be backed up as corrupt. → Task 2, `Load_LibraryFromM3WithoutRegions_LoadsWithEmptyRegions`.
2. **Center scaling with a photo larger than the monitor:** the texture is a crop, so mapping regions through the crop's destination would shift them. Regions must map through the full image's rectangle. → Task 1 `RegionView` tests and Task 3 `Build_CenterCrop_MapsThroughFullImageRect`.
3. **Corrupt or hostile region data over IPC or on disk** (NaN, points outside 0–1, 2-point polygons, null lists, 10 000 points): rejected at the boundary, never reaching the rasterizer. → Task 2 validation tests; engine checks `IsValid` (Task 6).
4. **Undo while dragging or while the soft-edge slider has an uncommitted change:** undo must cancel the live change, not jump two steps back. → Task 4 `Undo_DuringDrag_CancelsDragAndKeepsHistory`, `Undo_WithUncommittedFeather_RevertsOnlyThatChange`.
5. **Wide soft edge on a 4K monitor while dragging live:** a full-resolution CPU blur would stall the engine's render thread. The mask is rasterized at reduced resolution when σ is large. → Task 3 `Build_WideFeather_DownscalesMask`.

### Task 3: Mask rasterizer (Core)

**Files:**
- Create: `src/LiveWallpaper.Core/Regions/RegionMask.cs`
- Test: `tests/LiveWallpaper.Core.Tests/Regions/RegionMaskTests.cs`

**Interfaces (Produces):**
```csharp
public sealed record MaskImage(int Width, int Height, byte[] Pixels);   // row-major, 1 byte per pixel, 255 = effect fully shown
public static class RegionMask
{
    public const double BlurSigmaAtMaskPx = 3;   // downscale so σ is about this many mask pixels
    public const double MinScale = 0.125;
    public static double ScaleFor(double sigmaPx); // 1 when σ ≤ 3, else max(0.125, 3/σ)
    public static MaskImage? Build(RegionSet set, RectangleF imageBounds, Size target); // null when set has no regions
}
```
Algorithm (the tests don't fully determine it):
- `featherPx = FeatherPct/100 × imageBounds.Width`, `σ = featherPx/2`, blur only when `featherPx > 0.5`. Mask size = `ceil(target × ScaleFor(σ))` (at least 1×1); polygon points go image → screen (via `imageBounds`) → mask pixels (× maskW/targetW, × maskH/targetH); σ in mask pixels = σ × scale.
- Fill **each region separately** with nonzero winding, 4 sub-scanlines per row (y + (k+0.5)/4) and exact fractional horizontal span coverage, into a per-row `float` buffer; union into the byte mask with `max`.
- Blur: three box blurs per axis approximating the Gaussian (box widths from `wIdeal = sqrt(12σ²/3 + 1)`; `wl` = largest odd ≤ wIdeal, `wu = wl + 2`, `m = round((12σ² − 3wl² − 12wl − 9) / (−4wl − 4))`, the first `m` passes use `wl`, the rest `wu`), sliding int sums on bytes, **clamp-to-edge** at the frame border (a region touching the screen edge stays solid there; the preview faded it — documented in `docs/regions.md`).
- Invert last: `255 − value`.

```csharp
public sealed class History<T>   // MaxEntries = 100; Current, CanUndo, CanRedo, Push(T), Undo() → T, Redo() → T
public enum OverlayShapeKind { Edge, SelectedEdge, Handle, SelectedHandle, Ghost }
public readonly record struct OverlayShape(OverlayShapeKind Kind, RegionPoint A, RegionPoint B); // image coords; circles have A == B
public sealed class RegionEditor
{
    public const double HandleRadiusDip = 6, HandleHitDip = 9, EdgeReachDip = 6, VertexClearanceDip = 12;
    public RegionEditor(RegionSet initial);
    public event EventHandler? Changed;          // raised after anything visible changes
    public RegionSet State { get; }              // working state (includes an in-progress drag)
    public int? SelectedRegion { get; } public int? SelectedVertex { get; }
    public bool IsEnabled { get; }               // false while outlines are hidden
    public bool CanUndo { get; } public bool CanRedo { get; } public bool CanAddRegion { get; }
    public void SetView(RegionView? view);
    public void SetEnabled(bool enabled);
    public void PointerDown(RegionPoint screen); public void PointerMove(RegionPoint screen); public void PointerUp();
    public void RemoveVertexAt(RegionPoint screen);   // right-click on a handle of the selected region
    public bool DeleteSelectedVertex();               // Delete key; true when it removed one
    public void AddRegion(); public void DeleteSelectedRegion();
    public void SetInvert(bool invert); public void SetFeather(double pct, bool commit);
    public void Undo(); public void Redo();
    public IReadOnlyList<OverlayShape> Overlay();     // empty when disabled
}
```
Rules (port of `regionEditor.js`; hit distances are DIPs × `view.Scale`):
- Pointer down: on a handle of the selected region → select vertex and start a vertex drag; else on the ghost point → insert a vertex there (uncommitted), select it and drag it; else the topmost region containing the point → select it and start a body drag; else clear the selection.
- Drags clamp the pointer with `ClampToVisible` and use `VisibleBounds` as the bounds for `MoveVertex`/`Translate`. Pointer up commits once per drag (only if the state changed). The ghost (closest point on an edge of the selected region within reach, hidden within `VertexClearanceDip` of a vertex or at `MaxPoints`) updates on pointer move when not dragging.
- A commit pushes only when the state differs from `History.Current`.
- **Fixes:** `Undo`/`Redo` end any drag without committing, drop the selection (region and vertex) and the ghost; `Undo` with an uncommitted change (drag or feather) reverts to `History.Current` without stepping back (`CanUndo` is true while dirty); `SetEnabled(false)` cancels a drag, drops the selection, and makes pointer and Delete input no-ops and `Overlay()` empty.
- `AddRegion` adds `CreateQuad(view?.VisibleBounds ?? Unit)`, selects it, commits; no-op at `MaxRegions`. `SetFeather` clamps to [0, 10].
- Overlay: every region's edges (`SelectedEdge` for the selected one), handles of the selected region (`SelectedHandle` for the selected vertex), the ghost.

### Task 7: Overlay renderer (Rendering)

**Files:**
- Create: `src/LiveWallpaper.Rendering/RegionOverlayRenderer.cs`, `Shaders/RegionOverlay.hlsl`
- Test: `tests/LiveWallpaper.Windows.Tests/RegionOverlayRendererTests.cs`

**Interfaces (Produces):** `public sealed class RegionOverlayRenderer(GpuDevice gpu) : IDisposable { public const int MaxShapes = 1100; void Draw(ID3D11RenderTargetView target, Size targetPixels, RectangleF imageBounds, IReadOnlyList<OverlayShape> shapes, float scale); }`

Approach: shapes go into one constant buffer (2 × `float4` per shape: endpoints in pixels; kind and radius), `DrawInstanced(4, n)` with each instance a quad around the shape's bounding box; the pixel shader computes the distance to the segment (a circle when A == B) and returns premultiplied colour.
