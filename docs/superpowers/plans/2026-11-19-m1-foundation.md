# Milestone 1 — Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public repo with green Windows CI and a downloadable engine. The engine shows a still image behind the desktop icons on every monitor, survives Explorer restarts and display changes, and exits cleanly. The user verifies it on their Windows 11 laptop with two external monitors.

**Architecture:**
- The engine is a Win32 + Direct3D 11 executable with no WPF. M1 has no settings UI: the engine is driven by command-line verbs (`--set`, `--stop`, `--list-monitors`, `--dump-desktop`).
- All platform-independent logic lives in `LiveWallpaper.Core` (`net10.0`), so its tests run on the Mac. Windows code is built on the Mac via `EnableWindowsTargeting` and tested on GitHub Actions `windows-latest`.

**Tech Stack:** C# / .NET 10 LTS SDK, Vortice.Windows 3.8.3 (Direct3D11, DXGI, D3DCompiler, Direct2D1 for its `Vortice.WIC` namespace), `LibraryImport` P/Invoke, xUnit v3, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-19-live-wallpaper-design.md` (sections 3, 5.1–5.5, 5.11, 7, 8)

## Global Constraints

- Target `net10.0` for Core and its tests, `net10.0-windows` for everything else, x64. SDK pinned in `global.json` to the 10.0 feature band installed in Task 1.
- **Dependencies (listed for approval with this plan; there are no others):**
  - `Vortice.Direct3D11` 3.8.3
  - `Vortice.DXGI` 3.8.3
  - `Vortice.D3DCompiler` 3.8.3
  - `Vortice.Direct2D1` 3.8.3 (provides `Vortice.WIC`)
  - `xunit.v3` 4.0.3
  - plus whatever test-runner package xunit.v3 4.x's docs require for `dotnet test` on .NET 10. Check https://xunit.net before adding `Microsoft.NET.Test.Sdk` 18.12.0 / `xunit.runner.visualstudio` 4.0.1, and add only what is needed.
- Exact versions via `Directory.Packages.props` (central package management), and `RestorePackagesWithLockFile=true`. CI restores with `--locked-mode`.
- Nullable enabled, `TreatWarningsAsErrors=true`, `EnforceCodeStyleInBuild=true`, 4-space indentation, file-scoped namespaces.
- P/Invoke via `[LibraryImport]` (source-generated), with no CsWin32 or other interop packages.
- Log format `<ISO-8601 UTC> [<prefix>] key=value ...`. Verbose lines are only written when the environment variable `LIVEWALLPAPER_DEBUG=1` is set.
- Data folder `%LOCALAPPDATA%\LiveWallpaper\`.
- Never permanently change the user's Windows wallpaper.
- Never place a window above the desktop icons. If attaching fails, show a message and exit. The design's fuller fallback (temporarily showing the image as the normal Windows wallpaper) is deferred to Milestone 5.
- No Lively code is copied (GPL vs MIT).
- The repo is public from the first push: no secrets, no absolute personal paths, no images except ones generated by tests at runtime.
- Git: bootstrap commit on `main` (an empty repo needs one), then everything else on `feat/m1-foundation`, with conventional commits and a PR to `main` at the end. The user merges.
- Check the network before heavy downloads (`networksetup -getairportnetwork en1`). On a hotspot, ask before installing the SDK.

## Review Focus

1. **Explorer restarts while the engine runs:** Explorer destroys our child windows from under us. The engine must rebuild without crashing or leaking → `WallpaperWindow` disposal test with an externally destroyed handle (Task 8), and the rebuild path (Task 9).
2. **The user hand-edits `settings.json` and breaks it** (likely, since M1 has no UI): the engine backs the file up and runs on defaults → `SettingsStore` corrupt-file tests (Task 2).
3. **The image is missing, corrupt, not an image, or huge** (e.g. a 20000×10000 panorama): that monitor is skipped with a log line, the others still work, and huge images are decoded at display size → `WicImageLoader` tests (Task 7) and `ComputeDecodeSize` cap tests (Task 3).
4. **A monitor sits left of or above the primary** (negative coordinates), **or monitors have different DPI:** each window lands exactly on its monitor → `DesktopCoordinates` tests (Task 3).
5. **The engine is launched twice, or `--set` is run while it's running:** there's still exactly one renderer, and the running one reloads → `SingleInstance` test (Task 8) and `--set` signalling (Task 9).

**Interfaces:**
- Produces:
  ```csharp
  public sealed record DecodedImage(int Width, int Height, int Stride, byte[] Pixels); // 32bpp premultiplied BGRA
  public sealed class ImageLoadException(string message, Exception? inner = null) : Exception(message, inner);
  public static class WicImageLoader
  {
      public static Size ReadSize(string path);
      public static DecodedImage Load(string path, Size decodeSize);
  }
  public sealed class GpuDevice : IDisposable
  {
      public static GpuDevice Create(bool useWarp = false);
      public ID3D11Device Device { get; }
      public ID3D11DeviceContext Context { get; }
      public ID3D11ShaderResourceView CreateImageTexture(DecodedImage image);
  }
  public sealed class WallpaperSurface(GpuDevice gpu, nint hwnd, Size pixelSize) : IDisposable
  {
      public ID3D11RenderTargetView BackBuffer { get; }
      public void Resize(Size pixelSize);
      public void Present();
  }
  public sealed class ImageQuadRenderer(GpuDevice gpu) : IDisposable
  {
      public void Draw(ID3D11RenderTargetView target, Size targetSize, ID3D11ShaderResourceView image, RectangleF destination);
  }
  public static class ShaderCompiler
  {
      public static ReadOnlyMemory<byte> Compile(string resourceName, string entryPoint, string profile);
  }
  ```

How each piece works:
- **`WicImageLoader`:** decoder → frame 0 → `IWICBitmapScaler` (Fant) to `decodeSize` → `IWICFormatConverter` to `GUID_WICPixelFormat32bppPBGRA` → `CopyPixels`. Any `SharpGenException`, `IOException` or `UnauthorizedAccessException` is wrapped in `ImageLoadException` with the file name (no full path in the message).
- **`GpuDevice.Create`:** hardware device with `BgraSupport`, or WARP when asked. Feature level 11_0 minimum.
- **`WallpaperSurface`:**
  - `CreateSwapChainForHwnd`: flip-discard, 2 buffers, `B8G8R8A8_UNorm`, `AlphaMode.Ignore`.
  - `Resize` releases the RTV, then calls `ResizeBuffers`.
  - `Present(1, 0)`.
- **`ImageQuadRenderer.Draw`:**
  - Clear the target to black.
  - Set a viewport of `targetSize`.
  - Draw a quad covering `destination`, with the vertex positions computed in the vertex shader from a constant buffer `float4 destRect` + `float2 targetSize`, and no vertex buffer.
  - Use a linear-clamp sampler, and let the viewport clip anything outside the target.

- Create: `src/LiveWallpaper.Windows/WallpaperWindow.cs`, `src/LiveWallpaper.Windows/MessageWindow.cs`, `src/LiveWallpaper.Windows/SingleInstance.cs`
- Test: `tests/LiveWallpaper.Windows.Tests/WallpaperWindowTests.cs`, `tests/LiveWallpaper.Windows.Tests/SingleInstanceTests.cs`

**Interfaces:**
- Produces:
  ```csharp
  public sealed class WallpaperWindow : IDisposable
  {
      public static WallpaperWindow Create();
      public nint Handle { get; }
  }
  public enum MessageWindowEvent { ExplorerRestarted, DisplayChanged, ReloadRequested, CloseRequested }
  public sealed class MessageWindow : IDisposable
  {
      public const string ClassName = "LiveWallpaper.Engine.MessageWindow";
      public MessageWindow(Action<MessageWindowEvent> onEvent);
      public static nint FindRunning();
      public static void PostReload(nint window);
      public static void PostClose(nint window);
      public void RunMessageLoop();
  }
  public sealed class SingleInstance : IDisposable
  {
      public static SingleInstance? TryAcquire(string name);
  }
  ```

How each piece works:
- **`WallpaperWindow`:** class `LiveWallpaper.WallpaperWindow`, `WS_POPUP` with `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE`, and a background brush of null. It's created hidden; the engine shows it after attaching. `Dispose` calls `DestroyWindow` only if `IsWindow(handle)` is true.
- **`MessageWindow`:** a **hidden top-level window**, not `HWND_MESSAGE`, because message-only windows don't receive the `TaskbarCreated` and `WM_DISPLAYCHANGE` broadcasts. It maps:
  - `RegisterWindowMessageW("TaskbarCreated")` → `ExplorerRestarted`
  - `WM_DISPLAYCHANGE` / `WM_DPICHANGED` / `WM_SETTINGCHANGE(SPI_SETWORKAREA)` → `DisplayChanged`
  - `RegisterWindowMessageW("LiveWallpaper.Reload")` → `ReloadRequested`
  - `WM_CLOSE` → `CloseRequested`

  Bursts are debounced with a 500 ms `SetTimer` before raising `ExplorerRestarted`/`DisplayChanged`.
- **`SingleInstance`:** a named mutex `Local\LiveWallpaper.Engine`, using `createdNew`.

### Task 9: Engine executable

**Files:**
- Create: `src/LiveWallpaper.Engine/LiveWallpaper.Engine.csproj` (`WinExe`, `net10.0-windows`, `RuntimeIdentifiers win-x64`, `ApplicationManifest app.manifest`), `src/LiveWallpaper.Engine/app.manifest`, `src/LiveWallpaper.Engine/Program.cs`, `src/LiveWallpaper.Engine/EngineHost.cs`, `src/LiveWallpaper.Engine/ConsoleOutput.cs`

**Interfaces:**
- Consumes: everything above.
- Produces: `LiveWallpaper.Engine.exe` with the verbs from `EngineCommand`.

Behaviour:
- **`app.manifest`:** `PerMonitorV2` DPI awareness, Windows 10/11 `supportedOS`.
- **`ConsoleOutput`:** calls `AttachConsole(ATTACH_PARENT_PROCESS)` for CLI verbs so their output appears in the terminal they were run from.
- **`--list-monitors`:** prints `Id`, bounds, DPI and primary flag, one monitor per line.
- **`--dump-desktop <file>`:** runs `DesktopHost.Prepare` (to spawn WorkerW), then writes `DesktopSnapshotter.Capture()` JSON plus the classified plan to `<file>`.
- **`--set`:**
  1. Resolve the path with `Path.GetFullPath`.
  2. Validate it with `WicImageLoader.ReadSize`. On failure, print an error and exit with code 1.
  3. Write the assignments: `all` becomes one entry per current monitor.
  4. If an engine is running, call `MessageWindow.PostReload(FindRunning())`.
- **`--stop`:** `PostClose(FindRunning())`. Exit code 0 even if none is running.
- **Run:**
  1. Run `SingleInstance.TryAcquire`; if null, exit 0.
  2. Initialise `Log` (prefix `engine`).
  3. If `UncleanShutdownMarker.WasUncleanShutdown()`, call `DesktopRestorer.RepaintWallpaper()` and log it. Then `MarkRunning()`.
  4. Register an `AppDomain.UnhandledException` handler that tries the restore and `MarkStopped()`.
  5. Create `GpuDevice`, `ImageQuadRenderer` and `MessageWindow`.
  6. `Build()`:
     1. Enumerate monitors.
     2. `Prepare()` the desktop. If the plan is `Unsupported`: `MessageBoxW` saying "Live Wallpaper couldn't attach to your desktop. Run `LiveWallpaper.Engine.exe --dump-desktop desktop.json` and share the file.", log it, and exit code 2.
     3. For each monitor with an assignment: `ReadSize` → `ComputeDecodeSize` → `Load` → texture → `WallpaperWindow.Create` → `Attach` → `ShowWindow(SW_SHOWNA)` → `WallpaperSurface` at the monitor's pixel size → `Draw` with `ComputeDestination` → `Present`.
     4. An `ImageLoadException` skips that monitor with a log line.
     5. Monitors without an assignment get no window.
  7. Map the events:
     - `ExplorerRestarted` / `DisplayChanged` / `ReloadRequested` → `Teardown()` then `Build()`
     - `CloseRequested` → `Teardown()`, `RepaintWallpaper()`, `MarkStopped()`, then exit the loop

  `Teardown()` disposes surfaces, textures and windows in that order, and tolerates windows Explorer already destroyed. There is no per-frame loop in M1: it presents once per build.
